# Вставка своего SQL во вкладке DDL — дизайн

Дата: 2026-10-03

## Цель

В боковой панели редактора, во вкладке DDL, пользователь может вставить свой SQL и получить диаграмму.

## Решения

- Вставленный SQL **заменяет** текущую диаграмму (таблицы и связи). Слияния нет.
- Если диаграмма не пустая, перед заменой показывается подтверждение.
- Живого обновления диаграммы при наборе нет. Только явная кнопка «Применить».

## UI

Файл: `src/pages/editor-page/side-panel/ddl-section/ddl-section.tsx`.

- Вверху вкладки переключатель режимов: **«Из диаграммы»** и **«Свой SQL»**.
- «Из диаграммы»: текущее поведение (SQL только для чтения, `AuthBlurGate`, `CodeSnippet`).
- «Свой SQL»: редактируемый Monaco (`Editor` из `components/code-snippet/code-snippet`), под ним статус проверки и кнопка «Применить».
- После успешного применения режим возвращается на «Из диаграммы».

## Логика

- Проверка: `validateSQL` и `parseSQLError` (как в `dialogs/common/import-database/import-database.tsx`), с debounce 500 мс.
- Статус: ошибка со строкой либо «найдено N таблиц, M связей» (компонент `SQLValidationStatus`).
- Диалект: `diagram.databaseType`.
- Применение: `sqlImportToDiagram` строит таблицы и связи, затем они заменяют данные текущей диаграммы через контекст `useChartDB`. Точный метод замены (`updateDiagramData` или `loadDiagramFromData`) уточняется в плане.
- Кнопка «Применить» отключена, пока SQL пустой или невалидный.

## Ошибки

- Невалидный SQL: сообщение и подсветка строки, диаграмма не меняется.
- SQL без таблиц: «Таблицы не найдены», применение недоступно.
- Диаграмма не меняется ни при каком сбое парсинга.

## Тесты

- Юнит-тесты (vitest, по образцу `import-database.test.tsx`): валидный SQL применяется; невалидный блокирует кнопку; непустая диаграмма требует подтверждения; пустая применяется без него.
- Ручная проверка в браузере (playwright): вставка DDL, появление таблиц на холсте.

## Вне объёма

Слияние с существующими таблицами, живой предпросмотр, автоопределение диалекта.
